# 合同转单据工作台

入口：项目管理台账 → 单据自动生成 → 导入合同 / 新建单据任务。

上传及重新提取流程：读取文本 → 匹配已登记合同模板特征 → 命中则用模板规则提取，否则自动使用通用文本/表格规则。首批登记2026服务及2025设备、集成、培训、软件销售合同；标题和全部关键条款特征均符合才命中，冲突时回退。识别方式、模板名称、依据和规则版本随合同保存并展示。模板匹配不是正式单据版式生成，也不代表合同已审核；采购/旧DOC等尚未登记类型不强行套用。通用识别并非AI/OCR，扫描件仍不支持。

“我的合同”支持按文件名、合同编号、客户搜索，查看上传时间、单据数量和归档状态，下载上传原件。归档合同保留原件、清单和全部单据，禁止修改和生成；恢复后可继续使用。归档不删除文件，列表默认显示在用合同，可切换已归档或全部。已有上传合同自动显示，无需重新上传。

上传 DOCX 或文本 PDF（最大20MB），核对合同信息及明细并保存，然后勾选明细、填写本批次数量、确认核对，生成送货单、到货签收单或验收单 Word 草稿。历史文件按合同保存，可再次下载。

DOCX 使用表头规则识别，包含名称/内容、型号、单位、数量及原始表格行号。无法可靠提取的数量留空，必须核对。PDF 仅提供文字，明细需补录。旧版 DOC 需转为 DOCX。

上传时生成可编辑结构化候选：合同编号、甲方（客户候选）、乙方、含税总额、税率、服务/设备明细、付款节点和付款/验收条款摘录。支持服务项目表头与“2台”等数量单位拆分；付款节点保留比例、金额、支付天数和条件。规则未匹配的字段留空，不推断角色、交付性质或日历日期。旧合同可点击“从原件提取结构化内容”预览，核对保存后持久化；预览不修改已有记录和原件。保存保留既有明细ID，新明细获得新ID。付款节点暂不自动创建回款任务。

导出使用通用草稿版式，不是公司正式模板。扫描件OCR、AI语义抽取、正式模板映射、签收件上传、跨批次实际履约数量统计尚未实现。SN字段接收文本，不具备设备码语义校验。生成草稿不代表实际发货或验收。

合同、原文件、明细版本和草稿保存在当前登录用户的 contract_documents 目录；API不接受客户端指定归属用户。未知合同、跨用户下载均拒绝。保存与生成包含版本检查；数量须为有限正数，不能超过当前合同数量。

验证命令：`python3 -m unittest tests.unit.test_contract_documents -v`；前端：`pnpm --dir ai-office-assistant-web run build`。
