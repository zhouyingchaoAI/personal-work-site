## 第 2 页｜建设思路：把个人经验转化为组织能力

### 要解决的不是"没有系统"，而是"经验随人走"

| 结构性问题 | 建设思路 | 今天做到的程度 |
|---|---|---|
| 决策链长、参与方多，任一环节没人说得上话就白做 | 五类单位 × 九个阶段的决策链模板，量化"应覆盖 / 已覆盖 / L3 以上" | 已建：41 格模板与热力图，按账号数据计算 |
| 项目 5–8 年、人员 2–3 年一换，关系断在交接 | 关系边、动作留痕、责任指派与交接，让关系可移交 | 已建：指派 / 转移 / 协办 / 历史版本；交接包尚未生成 |
| 关系散落在微信、通讯录、饭局记忆 | 五层建档 + 系统评分，把"感觉"变成可比较的数字 | 已建：六维评分 L0–L5、衰减预警、单点风险 |

### 演进主线

**结构化沉淀（已建）→ 有依据地判断（规则已建，AI 未建）→ 有责任地行动（计划已建，主动推送未建）→ 从结果中学习（未建）**

**本页结论：系统的价值不在"存了多少"，而在"信息能否转化为组织行动"；今天完成的是第一步，后三步是接下来的工作。**

## 第 4 页｜数据真实状况：规模可观，质量决定 AI 能走多远

### 主账号数据规模（2026-09-24 生产快照）

| 动作留痕 | 993 | 含真实互动与计划 |

### 今天在驾驶舱上直接暴露的四个质量问题

| 现象 | 数据 | 对 AI 的影响 |
|---|---|---|
| 商机阶段高度集中 | 720 条在谈中 639 条在"合同签订"，"立项 / 设计联络"为 0 | 阶段流程失真，成单概率、漏斗分析不可信 |

**本页结论：数据"有了"但还没"活"。在接 AI 之前，先做一轮存量商机清洗和阶段回填，否则 AI 只会更快地放大错误。**

## 第 5 页｜业务架构：一个驾驶舱、四个业务板块、一套共用支撑

### 四个板块各自回答一个问题

| 业务板块 | 回答的问题 | 已建核心 |
|---|---|---|
| **经营分析** | 经营结果与结构好不好，差在哪 | 19 张子表导入 → 六分区看板，序时进度刻度，三层下钻，历史版本 |
| **五位一体客户经营** | 客户基础与对接关系稳不稳 | 区域地图、三种形态、三层关系评估、关系表三级导出 |
| **商机管理** | 后续签约有没有支撑 | 五 KPI、六阶段流程、赢率结构、签约节奏、优先推进 TOP5 |
| **项目作战地图** | 重点项目下一步打谁、谁去 | 决策链热力、引荐路径、候选人、阶段剧本、转计划 |

共用支撑：客户与组织（建档 / 导入 / 待补充）、关系维系（互动 / 计划）、责任统筹（指派 / 交接）、设置（权限 / 规则 / 区域 / 留痕）。

### 后续拟贯通的业务路径

**经营问题（经营分析）→ 相关商机（商机管理）→ 客户与关系（五位一体）→ 项目行动（作战地图）→ 执行反馈（工作台）**

现阶段各板块各自可用，跨板块只有"点击跳转"，没有数据级的自动关联与结果回流。

**本页结论：四个板块不另起炉灶，后续工作是打通数据链路，再叠加 AI。**

## 第 6 页｜总体目标架构：在业务底座之上建 AI 增强层

### 保留现有入口，新增五层能力（已有 / 规划分开标）

```text
触点层  Web 驾驶舱 / 工作台（已有）
        + 页面侧边 Agent + 企微 / 钉钉机器人 + 语音 / 文字速记（规划）
                          ↓
情报层  来源接入 → 内容抽取 → 待确认建议 → 人确认入库（规划；合同带入已有可复用）
                          ↓
判断层  规则评分（已有）+ LLM 解释 + 证据引用 → 风险 / 机会 / 缺口（规划）
                          ↓
行动层  晨报 / 作战建议 / 计划 / 材料 / 交接包 → 人员执行（计划与作战地图已有，主动推送规划）
                          ↓
学习层  建议—采纳—执行—结果 → 归因分析 → 人审核后校准规则（规划）
                          ↺ 反馈规则与经验
────────────────────────────────────────────────
底  座  五层 JSON + 历史版本 + 留痕 + Neo4j 图（已有）
        + CRM 技能、向量索引、Memory、Workflow 接入（规划）
贯  穿  权限零扩张 / 人工确认 / 证据追踪 / 离线评测
```

### 建设方式

复用平台已有的 Skill Runtime（`skill_runtime.py`）、Agent Runtime（`agent_runtime.py`）、Memory Layer（`memory.py`，SQLite FTS5）、Workflow Engine（`workflows.py`）——这四件已在周报、邮件、会议等 70 余个技能上跑通。联指经营要做的是"把自己的能力注册进去"，不是另建一套 AI 框架。

**本页结论：业务系统承载记录与流程，AI 负责理解信息、解释判断、生成建议；两者通过"技能"这一层受控连接。**

## 第 7 页｜AI 协同机制：通过技能调用业务能力，而不是让模型直接碰数据

### 各类能力分工

| 能力 | 职责 | 现状 |
|---|---|---|
| 业务数据与规则服务 | 正式记录、评分、预警、覆盖计算，作为判断依据 | 已有 |
| CRM Skills | 把查询 / 登记 / 建计划 / 改阶段封装为带 JSON Schema 参数与权限校验的调用 | 规划，首批 15–20 个 |
| LLM | 理解非结构化信息、辅助抽取、解释依据、组织文案 | 规划 |
| Agent | 结合页面上下文与用户问题，组织查询 → 分析 → 建议的步骤 | 平台已有，CRM 未接 |
| Workflow | 承接待确认、推送、跟进、结果记录等多步过程 | 平台已有，CRM 未接 |
| Memory 与向量索引 | 客户上下文摘要、经营偏好、相似客户 / 项目检索 | 规划 |

### 一次任务的调用路径

**用户提问 → Agent 拆步骤 → 技能校验能力与数据范围 → 读记录与规则结果 → LLM 结合证据生成回答**

读取：在当前用户授权范围内执行（复用 `crm_read_snapshot` 的同一套过滤）。
写入：先形成待确认内容，人确认后经技能执行，留痕记 `via=agent` 与建议 id。

### 首批技能示例

读：`crm.customer.brief`、`crm.risk.scan`、`crm.coverage.get`、`crm.path.find`、`crm.opportunity.get`
写（需确认）：`crm.action.log`、`crm.plan.create`、`crm.opportunity.update_stage`
报告：`crm.report.customer_health`、`crm.report.handover`、`crm.report.daily_brief`

**本页结论：模型负责理解和生成，技能负责受控调用，人负责确认和执行；权限边界一寸不动。**

## 第 8 页｜感知闭环：先减少录入负担，再增加信息来源

### 目标流程

```text
语音 / 文字速记        会议纪要 / 邮件        招标公告 / 人事任免
        └────────────────┬────────────────┘
                         ↓
   AI 抽取：参与人 / 触达层级 / 情报 / 客户承诺 / 下一步 / 是否客户主动
                         ↓
        待确认卡片：来源 + 原文片段 + 建议内容 + 匹配候选
                         ↓
                   业务人员确认或修改
                         ↓
   正式记录：动作（source=ai_extract）/ 计划 / 商机阶段变更 / 人物轨迹
```

### 为什么先做速记

今天 993 条动作全部人工录入；商机的阶段证据 0%。速记不依赖会议、邮件模块的数据质量，客户经理拜访后说两句就能落一条带情报的留痕，是最快见效、最能改善数据质量的入口。待确认队列可复用现有"待补充资料"的交互范式。

### 指标

单条留痕耗时（目标 20 秒内）、月留痕条数、留痕中"有情报产出"占比、抽取后被人工修改的比例。

**本页结论：AI 先帮人整理信息，不把未经确认的抽取结果当正式记录；速记是第一个入口。**

## 第 9 页｜判断闭环：从规则提示走向有证据的经营建议

### 已有规则（可解释）与规划中的 AI 解释

| 环节 | 内容 | 状态 |
|---|---|---|
| 获取依据 | 授权范围内的客户、关系、动作、商机、阶段材料 | 已有 |
| 调用规则 | 六维关系评分、分层衰减、单点风险、41 格覆盖、五维 / 三维组织评估、成单概率 | 已有，页面标注"暂估" |
| AI 解释 | 把规则结果、证据、模板、情报组织成"客户体检报告"与风险 / 机会 / 缺口提示 | 规划 |

### 每条判断的输出结构

**当前情况是什么 → 依据是什么（可点开） → 还缺什么信息 → 建议下一步做什么**

### 必须诚实的边界

现有评分与成单概率是规则参考，权重靠人拍、尚无归因验证；不能包装成"AI 预测"。第 4 页的数据质量问题（阶段集中、证据为空）会直接限制判断质量，需同步治理。

**本页结论：不仅告诉使用者"有风险"，还要说明依据和待核实事项；判断质量的上限由数据质量决定。**

## 第 10 页｜行动闭环：把判断转成具体的人、时间和工作

### 目标流程

```text
风险 / 机会 / 决策链缺口 / 签约临近或过期
                ↓
晨报或跟进建议：联系谁、为什么、准备什么材料与话术
                ↓
人确认后转为计划：负责人 + 到期时间 + 关联项目（已有计划机制）
                ↓
人员执行并登记真实互动与结果
                ↓
反馈至关系分、商机阶段与结果事件，形成后续依据
```

### 已有与规划

已有：计划与互动登记、逾期与到期排序的优先待办、督办队列、作战地图"第一步"可转计划。
规划：每日晨报推送、作战地图 LLM 化（话术草稿 + 材料清单 + 相似项目经验）、公开信息线索、离职 / 轮岗交接包。

### 必须区分的两件事

**建议被采纳 ≠ 工作已执行；计划完成 ≠ 发生真实互动。** 现有规则已明确：计划不计入互动评分、完成计划不刷新触达时间，防止"填计划刷分"。AI 行动层沿用这条底线。

**本页结论：AI 协助组织工作，业务人员承担确认、执行和结果反馈的责任。**

## 第 11 页｜学习闭环：把每次建议与执行变成可分析的经验

### 两张新增记录表（第 0 期就建）

| 记录 | 字段要点 | 解决的问题 |
|---|---|---|
| 建议记录 | 类型、内容、证据引用、目标用户、生成 Agent、状态（待定 / 采纳 / 编辑后采纳 / 拒绝 / 过期）、决定人与时间 | 建议是什么、给了谁、被怎么处理 |
| 结果事件记录 | 关联建议 / 动作 / 商机、指标前后值、观测时间 | 采纳之后发生了什么 |

### 反馈路径

**建议 → 采纳 → 执行 → 结果观察 → 归因分析 → 候选规则或经验 → 人审核发布（走现有规则版本机制）→ 支撑后续判断**

### 逐步沉淀的组织能力

关系评分权重与维系周期校准、阶段基准概率校准、话术与最佳实践库、相似客户 / 项目经验、季度组织能力报告。

### 前提条件

学习需要组织级汇总，而今天的数据是按账号物理隔离的（写只落本人命名空间）。跨账号脱敏聚合需要专门授权与制度共识，这是学习闭环真正的门槛，不是技术难度。

**本页结论："学习"落实为可追踪的结果反馈、人审核的规则校准和经验复用，不等于模型自行改写业务规则。**

## 第 12 页｜人机协同与治理：AI 参与经营，责任和权限不转移

### 职责分工

| 参与方 | 主要职责 |
|---|---|
| AI | 抽取整理、辅助分析、生成建议、汇总资料与提醒 |
| 业务人员 | 确认事实、决定采纳、执行工作、反馈结果 |
| 管理员 | 维护授权范围，审核并发布规则校准 |

### 四条运行边界（与现有权限模型一致）

- **权限不扩张**：Agent 会话绑定当前用户，技能走 `crm_capabilities` 与同一套数据范围过滤；跨账号分析需专门授权。
- **写入需确认**：AI 建议不直接覆盖正式记录；确认与写入过程留痕。
- **判断有证据**：记录来源、引用与依据，保留建议与结果的关联。
- **上线先评测**：脱敏评测集 + 采纳率 / 纠错率监控；AI 评估不用于人员考核（延续"评分是暂估"的既有红线）。

### 已有治理能力可直接承接

五级功能权限、五档数据范围、管理员任命、`audit.jsonl` 留痕、导出 SHA-256 追踪——这些今天就在运行，AI 层只需接入，不需重建。留痕不等同于防篡改审计，这一边界继续保留。

**本页结论：AI 扩大辅助能力，不扩大访问权限，也不替代人的经营责任。**

## 第 13 页｜实施路线与待决策事项

### 分期建设，每期验证一个闭环

| 阶段 | 建设重点 | 主要验证 | 初步节奏 |
|---|---|---|---|
| **第 0 期：地基** | 15–20 个 CRM 技能、侧边 Agent 只读问答、建议表与结果事件表、50 条脱敏评测集；**并行：存量商机清洗与阶段回填** | 权限隔离、留痕、回答准确率 ≥90%（目标） | 1–2 周 |
| **第 1 期：感知** | 速记 → 待确认 → 入库；客户体检报告；逐步接会议与邮件 | 留痕耗时、抽取纠错率、情报占比 | 约 1 个月 |
| **第 2 期：判断 + 行动** | 晨报推送、作战地图 LLM 化、公开信息线索、交接包 | 采纳率、转计划率、逾期跟进率、新人上手周期 | 1–2 个月 |
| **第 3 期：学习** | 归因分析、规则校准、话术库、相似项目推荐、季度组织能力报告 | 预测校准误差、经验引用数、资产净增长 | 季度级 |

### 需要拍板的事项

| 方向 | 事项 | 建议 |
|---|---|---|
| 入口与渠道 | 感知入口先做哪条；推送走企微还是钉钉 | 先速记；渠道按公司现有 IM |
| 数据治理 | 存量商机清洗责任人与口径；阶段与签约日期回填 | 第 0 期并行，业务方主导 |
| 实体与协同 | 项目助手与商机是否合并为同一实体 | 建议合并，避免两套项目数据 |
| 部署与数据 | 走现有 AI 网关还是独立部署；客户数据能否出内网 | 优先内网网关 |
| 治理与评价 | 评分考核红线、跨账号脱敏统计授权、归因报告可见范围、公开信息采集边界 | 制度先行，再开学习闭环 |

### 汇报结论

**已有基础**：四个业务板块，五层数据模型，规则计算，组织级权限与留痕，可降级的基础设施。
**真实差距**：零 AI 接入；数据规模可观但阶段与证据质量不足；跨板块未打通；测试基线有历史债。
**近期重点**：安全接入 AI（技能化）+ 数据清洗 + 速记入口，三件事并行。
**长期目标**：让经营信息持续转化为有依据的判断、可落实的行动和可复用的组织经验。

**联指经营助手：从"看清经营情况"，逐步走向"辅助组织经营行动"。**
