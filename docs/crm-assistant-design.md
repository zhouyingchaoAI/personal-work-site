# 联指经营助手 · 规划设计（先设计，暂不写代码）

> 对应概念：五位一体客户经营体系系统 —— 让关系从个人经验，变成组织资产。
> 本文只做规划与设计，落地范围按"可在本仓库现有架构上实现"裁剪，凡尚未接入的能力都明确标注，不用占位冒充。

---

## 1. 定位与要解决的真问题

轨交/集成行业客户关系的三个结构性痛点（PPT A2）：

1. **决策链长、参与方多**：业主、指挥部、总包、设计院、运营公司五类单位；定标、定技术、签验收、批付款分属不同人。
2. **周期远长于人员在岗时间**：项目 5–8 年、人员 2–3 年一换，关系断在交接上。
3. **关系散落在个人身上**：躺在微信、通讯录、个人记忆里，无法评估、交接、复用。

联指经营助手要把"关系"从个人经验**结构化为组织资产**：可建档、可评分、可预警、可推荐、可交接。

作为办公助手的**新增一级模块**（与项目助手、项目管理台账平级），菜单 `crm`，名称"联指经营助手"，归类"协作与效率"。

## 2. 与现有平台的关系（复用，不重造）

| 已有能力 | 复用方式 |
|---|---|
| 用户体系 / SSO / 角色 | 直接用 `authState` 与 `session`，全部数据按登录用户隔离，API 不接受客户端指定归属用户 |
| 项目助手 `project.py` | 客户经营的"项目关联层"与项目助手的项目打通：一个项目 → 一条决策链覆盖度 |
| 项目管理台账 / 合同 `contract_documents.py` | 合同中的甲方/乙方/客户候选可一键落成客户单位与联系人 |
| 每用户 JSON 存储（`user_data/<user>/<feature>/`） | 客户经营沿用同一持久化范式，无需引入新数据库 |
| 会议助手 / 邮件助手 | 后续作为"动作留痕"的情报来源（拜访纪要、往来邮件）——二期接入 |

**基础设施（已落地，2026-09-08）**：Neo4j / Redis / Celery 三件套已按"可选增强 + 优雅降级"接入，JSON 仍是可靠数据源：
- **Neo4j**（`crm-neo4j`，bolt://crm-neo4j:7687）：关系图谱投影，按 `owner=用户` 子图整体重建，支撑 `shortestPath` 二度引荐路径与度中心度。任一时刻可从 JSON 重放。
- **Redis**（`crm-redis`）：`crm_overview` 结果缓存（TTL 300s，写操作即失效）+ Celery broker/backend。
- **Celery**（`personal-work-celery`，worker+beat）：写操作后异步 `crm_sync_graph_task` 同步图谱；每日 07:30 `crm_daily_decay_scan` 全量重算衰减与缓存。
- **降级**：任一服务不可用时自动回退——图算法用 Python 内存 BFS、无缓存直算、Celery 不可用则内联同步，主流程绝不阻断。`/api/crm/infra` 可查引擎在线状态，页面顶部显示引擎徽标。

相关文件：`backend/crm_graph.py`（驱动接入/缓存/图查询）、`backend/celery_app.py`（Celery 应用与任务）、compose 服务 `crm-neo4j`/`crm-redis`/`personal-work-celery`。

## 3. 五层数据建模（PPT A3 落地）

沿用每用户 JSON，目录 `user_data/<username>/crm/`。五层对应五类记录，均带 `id`（uuid）、`created_at`、`updated_at`、`version`：

### 第1层 单位层 `units/*.json`
- 字段：`name` 单位名、`type`（主管/业主/总包/设计/运营）、`line_scale` 线网规模、`bid_preference` 招标偏好、`history` 历史合作、`win_rate` 中标率、`region` 城市。
- 来源标记 `source`：手工录入 / 合同带入 / 项目带入。

### 第2层 人物层 `people/*.json`
- 字段：`name`、`unit_id`（所属单位）、`title` 职务、`decision_role`（定标/定技术/签验收/批付款/影响者）、`power_radius` 权力半径、`influence` 影响力评分(0–100)、`stance` 立场（支持/中立/反对/未知）、`career_track` 职业轨迹（历任单位列表，**本行业金矿**）、`rotation_window` 轮岗窗口。
- 隐私：只记业务相关字段，不采集与业务无关的个人信息（PPT A7 右下注释）。

### 第3层 关系层 `relations/*.json`（视觉重点）
- 一条 = 我方某人 ↔ 客户某人的一条边。
- 字段：`our_member`（我方人，用平台用户或自由文本）、`person_id`（客户人）、`strength` L0–L5、`source` 关系来源、`intro_path` 引荐路径、`last_touch` 最近触达日期、`decay_state`（正常/预警/告警）、`single_point_risk` 单点风险标记（该客户是否只有一个人能碰）。

### 第4层 动作层 `actions/*.json`
- 一条 = 一次对客户的动作/触达。
- 字段：`relation_id`、`type`（拜访/电话/饭局/技术交流/方案汇报…）、`level` 触达层级、`intel` 情报产出、`cost` 投入成本、`effective` 有效性标记、`happened_at`、`bidirectional` 是否客户主动（权重×3，见 A4）。

### 第5层 项目关联层 `links/*.json`
- 四元组：`project_id` · `decision_node`（立项/设计/招标/定标/履约/验收/付款）· `person_id` 客户人 · `our_member` 我方人。
- 聚合输出：某项目的**决策链覆盖度**（应覆盖 N、已覆盖 M、L3 以上 K）。

> 明细/记录 ID 一次生成后固定，跨版本、跨批次可追踪（吸取合同模块"每次保存重生成 ID 不利追踪"的教训）。

## 4. 关系强度算法与衰减预警（PPT A4 落地）

### 4.1 强度分（决定 L0–L5，系统计算非自评）
六个维度（六芒星雷达）：

| 维度 | 取值来源 | 权重 |
|---|---|---|
| 触达近因 | 最近一次动作距今天数（越近越高） | 中 |
| 动作深度 | 动作类型层级累计 | 中 |
| **双向性** | 客户主动来找的动作占比 | **高（×3）** |
| 情报质量 | 有效情报产出数量 | 中 |
| 关键时刻 | 是否在定标/验收等关键节点触达 | 高 |
| 多点触达 | 我方多人是否都能触达该客户 | 中 |

加权归一 → 分数映射到六级：
`L0 未接触 → L1 认识 → L2 可对话 → L3 可信任 → L4 可协同 → L5 关键盟友`

### 4.2 衰减预警（按层级设阈值）
- 高层 90 天、中层 45 天、基层 21 天未触达 → 进入预警；再逾期 → 告警。
- 列表用绿→橙→红热度条呈现，仪表盘顶部汇总"X 条关系待维系"。
- 一期用**当日定时扫描 + 打开页面时实时计算**（本仓库无 Celery，暂不做后台异步任务队列，用登录/进入模块时惰性刷新 + 可选的每日一次脚本）。

## 5. 可视化（PPT A5 核心页落地）

模块首页两块核心视图：

### 5.1 关系网络图谱
- 中心=我方节点，向外五组客户簇（主管/业主/总包/设计/运营，各配色）。
- 节点大小=影响力；连线：粗金实线=紧密(L4+)、青线=一般(L2–3)、灰虚线=待建立(L0–1)。
- 节点悬浮"最近维系 N 天"；缺口节点红圈标"关系缺口"。
- 前端用轻量力导向图（如 `@antv/g6` 或 d3-force；优先选已在依赖里的库，没有则评估体积后引入 g6）。

### 5.2 决策链热力图
- 行=五类单位，列=立项·设计·招标·定标·履约·验收·付款。
- 格子颜色=覆盖强度（深蓝未覆盖 → 青绿 → 金强覆盖）；定标/验收缺口标红。
- 底部数据条："应覆盖 12 · 已覆盖 7 · L3 以上 3"（真实按当前数据计算，非写死）。

## 6. 项目作战地图（PPT A6 落地）

针对某个项目，系统回答"该派谁去、走哪条路"，六步流水线：

1. **拉模板**：调取该城市该业主的决策链模板（预置几套行业模板 + 可编辑）。
2. **算覆盖**：匹配全员关系边，标出空白格。
3. **找路径**：对目标客户人做二度关系最短路径，强度乘积最优（内存图算法）。
4. **排人选**：候选我方人排序 = 关系强度 × 可用度 × 历史成功率。
5. **配动作**：按项目阶段匹配动作剧本（预置话术/动作建议）。
6. **定目标**：第一步做什么、何时打到 L 几。

输出一页"作战地图"：**打谁 / 谁去 / 走哪条路 / 第一步做什么**，可导出。
新人接手客户时，一页看懂：他是谁、我们什么关系、历史发生过什么、现在该做什么。

## 2026-09-08 业务导航与轨交阶段优化

新增「业务导航」为默认入口，呈现主管、业主、总包、设计、运营五方职责及账号内建档覆盖；五方属于客户协作分类，不代表法定或固定上下级架构。补充监理、招标代理、检测及评估机构的协作说明。

阶段模板保留原七节点，增加联调试运行、初期运营，区分工程验收、运营安全评估和接管；回款按合同节点可跨阶段。资料依据见 `docs/superpowers/specs/2026-09-08-crm-rail-design.md`，页面内也提供来源入口。业务模板为通用参考，需要按项目合同与属地要求确认。

交互：档案关键词/组织筛选，预警一键留痕；动作支持下一步、负责人、跟进日期和项目，业务导航中可关闭待办；可独立查看覆盖，点击矩阵登记决策节点；阶段切换清除旧建议。新增表单清除残留编辑 ID。

统计：默认 29 个适用单元格，模板非必需格不算缺口；登记额外格后纳入应覆盖数，L3+ 按唯一格计数。此值是产品参考模板，不是行业标准 KPI。仍按当前账号数据计算，未扩大为跨账号组织共享。

算法如实标注：候选按现有关系评分排序，同单位路径为待核实线索；尚未引入可用度/成功率数据，不宣称“强度乘积最优”。未归属单位的联系人不构成同事边。

## Excel 收集与自动录入

联指经营助手顶部提供模板下载和上传。`.xlsx` 工作簿包含填写说明、单位、联系人、关系、动作、项目决策链；表头星号必填，日期为 YYYY-MM-DD，是非使用下拉值。

顺序导入并用单位名称+姓名关联，动作再按我方对接人定位关系。重名歧义报错，不猜测归属。只新增、不覆盖；已有单位、人物、关系、节点跳过，完全相同的动作跳过。相同姓名的资料修改应在界面编辑，上传不会覆盖既有数据。有效行直接入库，错误行返回工作表和Excel行号，修正后重传。

限制5MB、500条数据、解压总量30MB；拒绝公式与异常表头。导入沿用CRM使用权限与账号隔离，批次完成后统一失效缓存并触发图同步。新增API：GET /api/crm/excel/template、POST /api/crm/excel/import。

### 默认模板简化

默认下载改为单张「客户收集表」，八列中仅单位名称、单位类型、姓名三列必填，其余城市、职务、决策角色、我方对接人、认识渠道选填。每行自动关联或新建单位、联系人及关系；对接人空白使用当前账号。结果数量按输入行计数（新增/补全行），不按拆分后的实体数计数。旧五表文件仍可上传。简版不生成虚构拜访动作或项目节点，详细信息可后续在页面补录。

### 页面快速建档

联指经营助手顶部以及新增联系人入口统一打开「快速建档」。必填单位名称、类型、姓名；已有单位搜索选择后带出类型，选填内容默认折叠。一次保存关联单位、人物、我方关系；同名歧义报错，已有资料不覆盖。保存并继续添加保留单位和我方对接人，清空联系人信息并定位姓名输入框。原编辑入口仍用于补充完整档案。

POST /api/crm/quick-create 复用简版导入的关联校验，沿用CRM权限和账号隔离；批量关联完成后统一触发图同步。

## 单位与人员组织架构

单位可选上级单位（parent_unit_id）；人物可选所属部门（department）、直接上级（manager_id）、负责事项（responsibilities）。旧数据缺失字段时按未登记展示，保存其他资料时保留已登记的组织字段。支持清空上级；拒绝自身/下级循环和其他账号的关联ID。

「组织架构」页提供单位/部门树和人员汇报树，可搜索、展开收起并直接编辑。人员允许跨单位汇报，以表达集团/子公司协作；不会由行政关系推断项目审批权。快速建档选填区支持组织字段，原三项必填不变；Excel简版维持8列，组织信息在页面补充。

## CRM 专项权限系统

入口「安全权限」仅超级管理员可见。角色为关闭、只读、编辑、编辑与导入，支持到期日；专项授权优先于旧助手开关，原有普通账号的入口授权默认只读。原用户管理页CRM开关改为只读提示，统一从专项权限页管理。

HTTP入口按能力校验，未授权返回403；撤销及过期下次请求生效。数据仍每账号隔离，包括组织架构、Excel及Neo4j投影。超级管理员可管理授权与查看元数据审计日志，但未开放读取他人CRM数据的接口。

日志仅记录操作者、接口、状态及授权对象/等级，不记录客户正文。文件存储user_data/.crm-security；应用没有删除日志入口，但这不是防服务器管理员篡改的外部审计系统，也不替代存储加密或备份访问管理。

删除账号会先关闭其专项授权，防止同名账号重建后继承旧授权。空模板下载不含客户数据，允许只读账号使用。

### 专项权限分级管理（2026-09-08）

超级管理员通过「联指经营助手 → 安全权限」指定或撤销客户经营管理员，不直接分配普通用户的 CRM 专项权限。客户经营管理员负责只读、编辑、批量导入授权、到期日和审计日志，不能任命或撤销其他客户经营管理员。任命独立于原有使用授权，持续到超级管理员撤销；撤销后恢复原使用授权（已过期的授权不恢复生效）。既有用户授权保留，不自动指定任何账号。所有检查均在服务端执行，任命和撤销进入审计记录；管理身份不授予跨账号读取客户数据的能力。

### 联指经营驾驶舱（2026-09-09）

联指经营助手默认进入联指经营驾驶舱，使用当前账号已授权的数据展示五方单位分布、交互关系网络、L0–L5 关系强度、L3+ 占比、维系预警、单点风险、未建立关系的联系人与待跟进行动。无历史快照时不显示趋势或增长率。支持指标跳转、刷新、大屏模式和窄屏排版；空数据引导建档，写操作仍受专项权限控制。数据来自现有总览、联系人、关系和业务导航接口，未新增跨账号数据访问。

### 四大经营区域（2026-09-09）

按公司口径使用东区、西区、中区、广东区，单位字段 business_region 与原城市 region 分开存储；未填写为未分区，不推断省市。快速建档、单位编辑支持选填区域，驾驶舱与客户档案共享区域筛选，图谱、关系、风险与待办按关联单位同步过滤。新版简版 Excel 第九列为选填经营区域，兼容旧八列模板。已有单位的区域不由导入覆盖，不一致时提示先在档案核实修改。该区域仅用于业务归类与筛选，不扩展跨账号数据权限。

### 公司经营收集模板（2026-09-08）

下载入口改为“客户经营收集表”：按区域、单位、部门、职务、姓名、手机、办公电话、邮箱、微信 / 其他联系、重要程度、支持程度、跟进轨迹、上次互动时间、本周互动计划组织，附计划日期、我方对接人、单位类型、城市及维系周期。仅单位和姓名必填，所有联系方式均为选填，单位类型默认业主单位。支持程度保留 -1/0/1/2 原始编码，不推断语义。历史轨迹存为联系人 imported_history，具体上次日期生成非有效、非主动的历史触达；计划以 record_kind=plan 存动作集合供待办使用，关系重算排除计划，完成计划也不改变触达。联系人可维护 importance、support_level、maintenance_days；重要/一般导入默认14/21天，显式周期优先，达到周期预警、两倍周期告警。既有非空档案不覆盖，仅补空字段，重复历史互动/计划跳过。兼容旧八列、九列、旧经营收集表及进阶工作簿。填写说明及虚构示例不参与导入。

### 页面与表格统一收集（2026-09-08）

快速建档弹窗升级为“客户经营信息收集”，按组织联系人、可选联系方式、关系判断与历史、本周计划、补充资料分组，对齐公司经营表的19个字段。仅单位与姓名必填，手机、办公电话、邮箱、微信 / 其他联系均可留空；旧快速建档接口仍兼容，新页面通过 format=business 调用与Excel相同的 crm_business_row 校验、补空、去重和计划入库逻辑。连续录入只保留单位、区域、城市、单位类型与对接人，清空其他人员字段和历史计划。更多组织信息保留为页面扩展选项。使用说明同步更新。

### 收集选项中文化（2026-09-08）
