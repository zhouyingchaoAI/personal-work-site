## 第一部分 定位：这个系统到底在解决什么

### 1.1 行业痛点

轨道交通与系统集成行业的客户关系有三个结构性问题：

1. **决策链长、参与方多。** 一条线路从立项到付款，主管单位（发改/住建/交通）、业主（建设公司/指挥部）、总包、设计院、厂商、运营公司都在里面。定标、定技术、签验收、批付款分别在不同人手上，任何一个环节没人能说上话，前面的工作都可能白做。
2. **项目周期远长于人员在岗周期。** 项目 5–8 年，客户经理 2–3 年一换、客户方也在轮岗。关系最容易断在交接上：老人走了，他知道"谁说了算、谁能牵线、上次答应了什么"，这些都跟着走了。
3. **关系散落在个人身上。** 躺在微信、通讯录、饭局记忆里。公司无法评估（这家客户到底关系好不好？）、无法交接、无法复用（另一个区域想找同一个设计院的人，不知道公司里谁认识）。

### 1.2 产品命题

**把关系从个人经验变成组织资产**：可建档、可评分、可预警、可推荐、可交接。这就是"五位一体客户经营体系"落在软件上的形态。

再往前一步——也就是本文后半部分要讨论的——**让 AI 基于这份组织资产持续给出行动建议，并从每一次行动的结果中学习**，使组织的客户经营能力不再随人员流动而衰减，而是随时间累积。

### 1.3 现状一句话

今天系统已经做到了"账本 + 计算器 + 驾驶舱 + 权限"：数据结构化了、分数能算了、大屏能看了、谁能看谁能改也管住了。**但没有任何 AI 参与**——`backend/crm*.py` 里没有一处调用 LLM、Agent 或 Skill；平台已注册 70 多个技能（周报、出差、邮件、会议、知识库、记忆、工作流、写作、资讯、报销……），没有一个属于客户经营。会议助手、邮件助手、知识库这三个天然的情报来源也都没接进来。所有情报靠客户经理事后手填，所有判断靠公式与阈值，所有行动靠人主动打开页面。

## 第二部分 现状全景：系统功能细节

### 2.1 数据模型：五层关系账本

存储范式是每账号 JSON：`user_data/<username>/crm/{units,people,relations,actions,links,staff,opportunities}.json`，每条记录带 `id`（一次生成永不变，跨批次可追踪）、`created_at`、`updated_at`、`version` 乐观锁；每次修改保留历史版本（`crm_record_versions`，可追溯旧值）。**JSON 是唯一可信源**，Neo4j、Redis、前端缓存都是投影，可随时从 JSON 重放。

**第 1 层 单位（units）**
- 基本：`name`、`type`（主管单位 / 业主单位 / 总包单位 / 设计单位 / 厂商 / 运营单位 / 其他，七类）、`region`（城市）、`business_regions`（经营区域：东区 / 西区 / 中区 / 广东区，可多区归属；未填为"未分区"，系统不从省市推断）。
- 组织：`parent_unit_id` 上级单位（拒绝自身/下级循环、拒绝跨账号 ID）、部门节点树（`/api/crm/department/node` 增删）、来源标记（手工 / 合同带入 / Excel 导入）。
- 行业属性（设计中预留）：线网规模、招标偏好、历史合作、中标率。

**第 2 层 人物（people）**
- 身份：`name`、`unit_id`、`department`、`title` 职务、`decision_role`（定标 / 定技术 / 签验收 / 批付款 / 影响者）、`manager_id` 直接上级（允许跨单位汇报，表达集团/子公司协作，但不由行政关系推断审批权）、`responsibilities` 负责事项。
- 经营属性：`importance` 重要程度、`support_level` 支持程度（保留 -1/0/1/2 原始编码，不推断语义）、`maintenance_days` 维系周期（显式周期优先；导入的重要/一般默认 14/21 天）、`imported_history` 历史跟进轨迹、联系方式（手机 / 办公电话 / 邮箱 / 微信等，全部选填）。
- 隐私边界：只记业务相关字段。

**第 3 层 关系（relations）——系统的视觉与算法中心**
- 一条记录 = 我方某人 ↔ 客户某人的一条边：`our_member`（平台账号或自由文本；可留空显示"待指派"）、`person_id`、`strength` L0–L5（系统计算，非自评）、`radar` 六维、`decay_state`（normal / warning / alarm）、`single_point_risk`、`source` 关系来源、`intro_path` 引荐路径、`last_touch`。
- 责任：指派 / 转移 / 协办人（`assignees`）、创建人与实际修改人分别记录；被指派人只能在授权范围内编辑，跨账号维护时不允许替换联系人。

**第 4 层 动作（actions）**
- 真实互动：`relation_id`、`type`（拜访 / 电话 / 饭局 / 技术交流 / 方案汇报…）、`level` 触达层级、`intel` 情报产出、`cost`、`effective` 有效性、`bidirectional` 是否客户主动（评分权重 ×3）、`happened_at`、`decision_node`（对应哪个决策节点）。
- 计划：`record_kind=plan` 的记录承载 `next_step`、`owner`、`due_date`、`project_id`、`completed_at`。计划不计入真实互动评分，完成计划也不刷新触达时间——这条规则是防止"填计划刷分"。

**第 5 层 项目关联（links + opportunities）**
- `links`：`project_id` × `decision_node` × `person_id` × `our_member` 四元组，聚合成某项目的决策链覆盖度。
- `opportunities`（商机）：`code` 编码、`name`、`owner_unit` 业主、`sales_stage` 六段销售阶段（立项 → 初设 → 招标（深化）设计 → 招标执行 → 设计联络 → 合同签订，前三段"定义项目"、后三段"赢得项目"，与后端 `OPPORTUNITY_STAGES` 一致）、`win_rate` 登记赢率、`status`、`region`、`manager`、`bid_date`、`contract_date`、`amount` 可参与份额（万元）、`outcome`（open / won / lost / cancelled）及变更时间、`stage_progress`（每阶段：附件材料、阶段关系人、状态、计划起止、已完成工作项、更新人）、`duplicate_of` 人工归并指向、`_shared_owners` 跨账号来源。

**员工（staff）**：我方组织目录（公司 / 部门 / 姓名 / 账号映射），用于"我方对接人"解析、客户经理名单、区域授权。

**真实规模（2026-09-24）**：主账号 239 个单位、939 个联系人、1227 条关系、993 条动作、746 条商机、165 名员工；另一账号 722 条商机（与主账号大量重码，已按编码去重）。

### 2.2 算法层：把主观感受变成可计算、可解释的数字

所有算法都在后端用纯 Python 实现，无模型、无外部服务依赖；每个输出都附带依据，页面上标注"暂估、不用于考核"。

**（1）关系强度评分 `crm_score_relation`**
六个维度各 0–100：
- 触达近因：最近一次动作距今 ≤30 天满分，线性衰减至 180 天为 0。
- 动作深度：有效动作数 × 25，封顶 100。
- 双向性：客户主动发起的动作占比（合成时权重 ×3，是唯一的高权重项——客户愿意主动找你，是关系质量最硬的证据）。
- 情报质量：产出情报的动作占比。
- 关键时刻：是否在定标 / 验收 / 招标 / 付款节点有触达，是则 100。
- 多点触达：我方触达该客户的不同成员数 × 50，封顶 100。
加权合成（双向性 3、其余各 1）后映射六级：≥85 L5 关键盟友、≥68 L4 可协同、≥50 L3 可信任、≥30 L2 可对话、≥1 L1 认识、0 L0 未接触。

**（2）衰减预警**
按人物层级默认阈值：高层 90 天预警 / 180 天告警，中层 45 / 90，基层 21 / 45；联系人自定义 `maintenance_days` 优先（到期预警、两倍告警）。每日 07:30 Celery `crm_daily_decay_scan` 全量重算并失效缓存；打开页面时也实时计算。

**（3）单点风险**
某客户人只有一个我方触点即标记；驾驶舱风险雷达、督办队列、关系评估都引用。

**（4）决策链覆盖 `crm_decision_coverage`**
模板：五类单位 × 九个轨交阶段（立项 / 设计 / 招标 / 定标 / 履约 / 联调试运行 / 验收 / 初期运营 / 付款，`crm_rail.py` 定义各阶段动作、交付物与关口）。默认适用 41 格（3+9+6+6+5+6+6，按单位类型只算相关阶段），模板非必需格不算缺口；登记额外格后纳入应覆盖数；L3+ 按唯一格计数。输出"应覆盖 N / 已覆盖 M / L3 以上 K"，热力图着色。系统明确标注：模板是产品参考，不是行业 KPI。

**（5）引荐路径与中心度 `crm_path_to_person` / `crm_graph_centrality`**
Neo4j 按 `owner=账号` 子图重建，`shortestPath` 求二度路径，返回节点 ids/names/hops/source；Neo4j 不可用时回退内存 BFS。作战地图与图谱的"金色路径"高亮用它。候选人排序目前按现有关系评分，同单位路径标为"待核实线索"；系统如实声明尚未引入可用度与历史成功率数据。

**（6）组织对接质量五维评估（公司与客户视角）**
岗位覆盖 30 / 关系质量 25 / 互动有效性 20 / 对接稳定性 15 / 维护责任 10；资料完整度独立计算；不足三个可评维度标"待评估"，其余按已有维度权重折算并标"暂估"。缺少支持程度或互动证据不记零分；计划与未来日期不计真实互动。按客户根组织汇总授权可见的下级关系，不取个人评分平均。

**（7）个人与客户组织三维评估**
关系质量 45 / 互动有效性 30 / 维系及时性 25；及时性在周期内 100、周期后线性下降、两倍周期为 0；无日期不计分。按"我方对接人 × 客户根组织"汇总，已可评联系人等权平均，同时显示可评人数/总人数。

**（8）评分规则可配置 `crm_quality`**
五维权重（可设零停用）、评级阈值、最低可评维度、互动窗口、主备人数、完整度提示线、关系强度占比、支持分值、五类组织岗位模板，统一存 `.crm-quality-settings.json`，带版本冲突保护和前后规则审计；公式不接受可执行表达式，"缺资料不记零分"等底线不可改。

**（9）商机成单概率（前端 `opportunityProbability.ts`）**
阶段基准概率：立项 10、初设 25、招标设计 45、招标执行 65、设计联络 82、合同签订 95。有登记赢率时 = 基准 ×0.6 + 赢率 ×0.4。证据调节：已到达阶段中有材料或关系人的比例 ≥60% 加 6、<20% 减 8；完全无材料无关系人减 6；有跟进计划加 3；夹在 2–98 之间；赢单 100、丢标/取消 0。输出 `reasons`（依据）与 `gaps`（缺口）文字，驾驶舱和商机详情都展示。

**（10）跨账号商机去重 `_crm_dedupe_opportunities`**
按编码合并，优先级：人工确认的 `duplicate_of` > 调用者本人副本 > 阶段证据多 > 更新时间新；导入预检把"其他账号已导入"列为重复原因。个人范围账号仍只见自己名下记录。

### 2.3 界面与工作流

#### 2.3.1 联合指挥驾驶舱（`Cockpit.vue` + `command/`）

共用固定外壳：Logo、渐变标题"联合指挥驾驶舱"、标语、刷新 / 全屏按钮、167px 图标侧栏（总体信息 / 经营分析 / 五位一体 / 商机管理 / 项目作战地图 / 系统设置）。切换看板不改变外壳（有回归断言）。

**总体信息**：1571×792 设计画布等比缩放，八个面板——
- 经营分析摘要：五个核心指标（指标 / 全年目标 / 当前达成 / 达成率），毛利率、费效比、营业利润三个 KPI 块，"重点"提示取全年达成最低项。
- 商机管理摘要：在谈数、可参与份额、阶段分布条、成单概率高/中/低、待指派提示。
- 五位一体摘要：客户 / 联系人 / 在维关系三连数，关系健康度（正常 / 预警 / 告警）分布，待维系与单点风险，五类客户数量。
- 项目作战地图摘要：≥1000 万重点项目数、金额前二项目、区域金额前二。
- 风险雷达：单点风险 / 未建关系 / 逾期跟进三数 + 高风险客户列表。
- 五类客户健康度与布局：内嵌五维雷达 + 分区光点图 + 五类布局列表（点击开关系网络）。
- 行动指挥台：今日待办 / 逾期待办 / 本周计划 / 需协调。
- 最近动态：商机新增、跟进记录流。

**经营分析**：从 Excel 标准模板导入 19 张经营子表（核心指标、作战平台结果与目标达成、产业结构、省份分布、费用明细与费用率、产业费用构成、订单质量、公司损益、现金流构成、收入支撑、回款转化率、预付条款、项目属性、机会点清单、滚动冲刺、年初预算承接、已完成订单明细），后端 `crm_compute_dashboard_data` 算出 26 个看板键。前端渲染六个分区：01 核心经营总览（六个 KPI 卡带年度序时进度刻度与超前/落后 pp、毛利率/费效比/营业利润目标差、三条现算结论）、02 经营结构（费用构成环图 + 预算执行、机会储备 + 阶段饼图）、03 区域经营（区域结果可切收入/毛利/最终利润、任务令、费用分摊与费用率热力、订单质量热力、省份对比、区域现金流与机会储备）、04 产业经营（目标贡献、毛利去向与效率、子产业与项目属性、合同条款与回款质量热力）、05 经营发展基础（项目年份现金流、收入支撑、预付条款与回款转化折线）、06 项目监测（滚动冲刺、年初预算承接、已完成订单三张长名称列表）。每张卡点击可放大 → 三层下钻：放大图表 / 数据表 / 原始来源表（19 张全部可达）。支持历史版本切换、模板下载、重新导入；口径说明按需展开。

**五位一体**：高德区域地图（配置后加载，未配置或离线回退内置省界图），三种形态按数据范围显示（客户经理 / 区域指挥 / 联合指挥），客户经理形态可在工具栏选人并上一位/下一位；地图上方一行全区统计（客户单位 / 联系人 / 待维系 / 待跟进，全区按去重口径）；四张区域卡（东/西/中/广东，点击聚焦与取消）；客户概况、优先跟进；底栏"关系网络 / 三层关系 / 项目作战 / 搜索"，三层关系浮层复用评估总览（公司覆盖 / 个人维系 / 组织渗透）并可进分层明细；"导出关系表"三级（联合指挥全部 / 区域 / 客户经理个人，含重要程度与支持程度列）。

**商机管理**（2026-09-24 重做）：五个图标 KPI（在谈商机含重点项目与覆盖区域；可参与份额含均值；概率加权预期含占比进度条；平均预测赢率含环形仪表与高中低数；需要关注 = 已过预计签约 + 待指派）、预测赢率结构（环图 + 数量与份额）、六阶段流程卡（定义/赢得双色，数量、份额、占比、柱高）、区域机会结构纵向柱、质量支撑三环（材料 / 关系 / 行动覆盖率）、预计签约节奏（已过期 / 本月 / 1–3 月 / 4–6 月 / 7–12 月 / 一年后 / 未填写）、优先推进 TOP5（名次徽标、阶段标签、赢率胶囊与进度条、加权价值与原始份额、负责人，一键"推进"进入商机）。

**项目作战地图**：≥1000 万在谈项目清单（区域 / 阶段 / 份额 / 负责人），进入单项目：决策链热力图（五类单位 × 九阶段）、当前阶段动作剧本与交付物、目标客户人二度引荐路径、候选我方人排序、"第一步做什么"建议，可转为计划（确认负责人与日期）。

#### 2.3.2 日常工作台

- **优先待办**（`Workbench`）：授权范围内 ≤8 项，逾期与到期排序；"今天先做这几件事"。
- **督办队列**（`ManagementQueue`，有管理能力的账号）：逾期跟进、14 天久未跟进、负责人缺失、单点风险四类；明确是"风险线索"，不伪装成已创建的协同任务。
- **四板块概览**（`BoardOverview`）：经营 / 客户 / 商机 / 跟进四块摘要，一键进驾驶舱。
- 移动端：页签下拉选择，390px 无横向溢出。

#### 2.3.3 客户与组织（`CustomerWorkspace` 及子视图）

**功能权限**：disabled / viewer / editor / importer / manager（客户经营管理员）。超级管理员任命或撤销管理员（不直接分配普通权限）；管理员负责只读 / 编辑 / 导入授权与到期日、查看审计，不能任命其他管理员。能力对象 `crm_capabilities` 输出：read / write / import / manage / supervise / appoint / register_action / batch_assign / approve_changes / complete_import_task / security_users / data_scope / regions / scope_company / scope_departments / expires_on / expired。

**数据范围**：self / team（本人及部门树下级）/ organization（指定公司 + 部门）/ regions（指定经营区域）/ all（仅超级管理员可授）。读取在 `crm_read_snapshot` 统一过滤；**写永远落本人物理命名空间，跨账号只读**；被指派事项的完成按可见关系与实际负责人授权。

**留痕**：所有 CRM API 经 `check_assistant_permission` 写 `audit.jsonl`（操作者、接口、状态、授权对象与等级，不记客户正文）；可见范围 = 数据范围（self 只看自己，team/organization 看子树成员，regions 看在授权区域有单位的操作者，总能看到针对自己的授权变更）。四类导出（关系表、组织架构、补充表、收集模板）页脚带导出人与时间，并记录 export 事件、文件名、筛选参数、字节数与 SHA-256。

**诚实边界（系统内明文标注）**：留痕不是防篡改审计系统，不替代存储加密与备份访问管理；评分是暂估不用于考核与排名；决策链模板是参考不是行业 KPI；删除账号先关闭其专项授权以防同名重建继承。

## 第四部分 目标：什么是"AI 原生的客户经营组织"

### 4.1 定义

不是给 CRM 加聊天框。判断一个组织是否"AI 原生"，看它的客户经营是否由四个 AI 驱动的闭环运转：

**感知闭环**——客户世界的变化自动进入系统。一次拜访说两句话就能变成结构化留痕；一封邮件、一场会议自动匹配到客户人；一条招标公告自动变成商机或阶段变更建议；一则人事任免自动更新人物轨迹。今天：0% 自动，100% 人填。

**判断闭环**——系统能回答"这家客户现在什么状态、风险在哪、机会在哪、下一步该做什么"，并且每句判断都能点开看证据。今天：能算分、能标红，但不能综合多源信息成结论，不能解释因果。

**行动闭环**——判断变成具体的人、时间、话术、材料，主动送到执行者手里；执行后结果自动回流。今天：有待办和作战地图，但生成靠模板，触达靠人打开页面，回流靠手填。

**学习闭环**——哪类动作在哪类客户、哪个阶段真正提升了关系强度或推进了商机，模型参数（评分权重、阶段基准概率、维系周期）据此校准；话术库、决策链模板、最佳实践随时间增厚。今天：权重可配但靠人拍，没有任何效果归因。

### 4.2 组织层面的含义

- **经验沉淀在系统里而不是人的脑子里**：客户经理离职，交接包一键生成；新人第一周就能知道"这家客户谁说了算、我们和谁关系最好、上次答应了什么"。
- **系统的每一条建议都来自组织经验**：作战地图不是通用模板，而是"过去三年公司在同类业主、同阶段做过什么、什么有效"的提炼。
- **组织的每一次行动都反哺系统**：采纳建议 → 执行 → 结果，形成数据，下一次建议更准。
- **能力随时间累积而不是随人员流动衰减**：这是"组织资产"四个字真正兑现的方式。

### 4.3 设计原则（与现有系统的诚实风格一致）

1. 交互 First，Chat Second：保留所有页面、表单、按钮；AI 是增强层，不替代操作路径。
2. AI 不直写可信源：所有抽取与生成先进"待确认"，人确认后入库并标 `source=ai_extract` 与原文引用。
3. 判断必带证据链：每条 AI 结论可点开看依据（动作、评分变化、公告原文、邮件片段）。
4. 权限零扩张：AI 只能看当前用户可见的数据，生成内容附数据范围声明；技能走现有专项权限与留痕。
5. 从第一天记录"建议—采纳—执行—结果"：没有这份数据，学习闭环永远做不了。
6. 评估先行：每个 Agent 能力上线前有脱敏离线评测集，上线后监控采纳率与纠错率。

### 5.1 CRM 技能清单（第 0 期最小集，命名对齐平台 `模块.动作`）

### 5.2 关键数据结构新增

- `crm_suggestions`（建议）：id、type（留痕抽取 / 阶段变更 / 风险 / 作战步骤 / 联系提醒）、payload、evidence[]（引用类型 + 引用 id + 原文片段）、target_user、created_by（agent 名）、status（pending / accepted / edited / rejected / expired）、decided_at、decided_by。
- `crm_outcome_events`（结果）：suggestion_id、action_id / opportunity_id、metric_before、metric_after、observed_at。
- 向量索引：客户单位、联系人、动作情报、商机描述、公告原文的嵌入，用于"找相似客户 / 相似项目 / 相关情报"。
- Memory：每个用户的经营偏好（常跑区域、习惯话术、汇报风格）与每个客户的上下文摘要（Agent 每次对话前注入）。

### 5.3 与权限的关系

- Agent 会话绑定当前登录用户，技能内部调用 `crm_read_snapshot` 同一套范围过滤；跨账号统计（学习层）只在脱敏聚合层进行，且需要专门授权（见第六部分待拍板问题）。
- 所有 AI 写入经"待确认"，确认者即写入者，留痕记录 `via=agent` 与 suggestion_id。

## 第六部分 迭代路线（按闭环推进，每期独立可交付）

### 第 0 期（1–2 周）：地基——让 AI 能碰到 CRM

交付：
1. 15–20 个 CRM 读写技能注册进 Skill Runtime，前端现有按钮不变。
2. 犇犇侧边 Agent 在客户经营页面内支持自然语言问答（纯读）："长沙地铁 8 号线决策链还缺谁？""李工最近三个月谁碰过？""东区哪些商机预计签约已经过期？"——回答附数据范围声明与可点击证据。
3. `crm_suggestions` / `crm_outcome_events` 两张表建好，哪怕暂时只有人工创建的建议也开始记录采纳与结果。
4. 离线评测集 v0：从真实数据脱敏抽 50 个问答样本，作为后续回归基线。

验收：技能全部可被审计；问答准确率在评测集上 ≥90%；无任何跨范围数据泄露（用现有权限测试夹具复测）。

### 第 1 期（约 1 个月）：感知闭环——少填表

交付：
1. **语音 / 文字速记 → 结构化留痕**：客户经理拜访后在手机或网页说 / 写两句话，Agent 抽出参与人（匹配联系人，歧义时给候选）、触达层级、情报、客户承诺、下一步、是否客户主动，生成待确认卡；确认即写入 `actions`（`source=ai_extract`，保留原文）。
2. **会议纪要 / 邮件 → 建议留痕**：接会议助手与邮件助手，按参会人 / 收发件人匹配客户人，生成建议卡；不自动写入。
3. **客户体检报告**：驾驶舱五位一体与客户档案一键生成，基于评分、动作、商机、覆盖写 300–500 字结论 + 证据链 + 三条建议。
4. **待确认队列**：复用"待补充资料"的交互范式，作为所有 AI 建议的统一入口。

指标：单条留痕录入耗时（目标从分钟级降到 20 秒内）、月留痕条数、留痕中"有情报产出"占比、抽取纠错率（用户编辑后入库的比例）。

### 第 2 期（1–2 个月）：判断 + 行动闭环——系统先开口

交付：
1. **每日晨报**（企微 / 钉钉 / 站内）：今天该联系谁（衰减到期、关键节点临近、预计签约将到或已过、逾期计划），为什么，建议话术与材料，一键转计划或标记"不需要"。
2. **作战地图 LLM 化**：结合决策链模板、引荐路径、历史动作剧本、相似项目经验（向量检索），生成可执行的"第一步"文案、话术草稿、材料清单；每一步可转计划并跟踪。
3. **公开信息采集**：招标公告 / 中标公示 / 政府与业主人事公告定时采集 → 商机新建或阶段变更建议、联系人轨迹更新建议（附原文链接）。
4. **交接包**：人员离职或轮岗时，按其名下关系与商机生成"他是谁、我们什么关系、历史发生过什么、现在该做什么"，接收人确认后完成责任转移。
5. **Agent 主动提醒的节流与偏好**：用户可设定接收频率与关注范围，写入 Memory。

指标：建议采纳率、晨报点击 / 转计划率、逾期跟进率下降、决策链覆盖率上升、单点风险数下降、新人上手周期（从入职到独立完成首次有效触达）。

### 第 3 期（季度级）：学习闭环——组织越用越聪明

交付：
1. **归因分析**：动作类型 × 客户类型 × 阶段 × 层级 → 关系分提升 / 商机阶段推进 / 赢单的贡献度；输出"什么有效"报告（例如"在招标执行阶段对设计单位做技术交流，后续 60 天内关系分平均 +18"）。
2. **参数校准**：评分权重、阶段基准概率、维系周期按归因结果离线计算候选值，管理员审核后走现有规则版本机制发布，页面展示"上次校准依据"。
3. **话术库与最佳实践**：从高效动作的情报与话术中自动提炼，标注来源与效果，作战地图生成时引用。
4. **季度组织能力报告**：关系资产总量与结构、L3+ 占比变化、单点风险消解、覆盖率、人均有效触达、预测赢率与实际赢单的校准误差、区域与个人对比（明确不用于考核）。
5. **相似客户 / 相似项目推荐**：向量检索支撑"这家新客户像谁，当年怎么打的"。

指标：预测赢率校准误差、关系资产净增长、单点风险数、话术库被引用次数、报告被管理层采纳的决策数。

### 贯穿各期的治理

- 权限零扩张、写入必确认、证据链必带、脱敏评测集必备。
- 合规：仅业务字段；外部采集限公开信息并记录来源与抓取时间；抽取内容保留原文引用。
- 明确不做：不用聊天替代表单；不做黑盒评分；不做未经确认的自动写入；不把 AI 评估用于人员考核。

## 第七部分 需要拍板的问题

1. **感知入口优先级**：语音 / 文字速记、会议纪要、邮件、公告采集，先做哪条？建议先做速记——它不依赖其他模块的数据质量，客户经理立刻受益。
2. **推送渠道**：企业微信还是钉钉？决定第 2 期机器人形态与身份打通方式。
3. **评分校准与考核红线**：数据驱动校准后评分会变动；"评分不用于考核"这条红线是否长期成立？若成立，需要在组织制度层面固化。
4. **跨账号学习数据**：学习闭环需要组织级汇总；是否允许在脱敏聚合后跨账号统计？谁有权看归因报告？
5. **公开信息采集边界**：招标网站、政府公告的抓取范围、频率、合规确认。
6. **项目助手与商机实体**：是否合并为一个"项目 / 商机"实体，避免两套项目数据长期并存。
7. **模型与部署**：LLM 走现有平台网关（已有 AI 安全网关与 FastGPT 接入）还是独立部署；客户数据是否允许出内网。

## 附录 C 术语

- **五位一体**：主管 / 业主 / 总包 / 设计 / 厂商（运营）五类客户单位与我方的协同经营体系。

- **建议（suggestion）**：AI 生成、待人确认的任何记录或行动提议。
