# CRM 第三批：商机详情与准确定位

目标：沿用已确认的极简评估，以单个商机为中心集中阶段、责任人、下一步和客户联系人，避免继续增加导航层级。

## 实施

- 工作台、客户详情传递具体商机，采用物理归属账号与记录 ID 组合定位。搜索仍保留自由文本，但跳转详情不依赖关键词命中第一条。
- 商机列表名称可打开详情抽屉；详情包含简短概况、下一步和客户联系人，其他项目资料折叠；编辑/推进建议复用已有流程。
- 待办按物理账号与完整商机编号匹配，排除已完成项；不同账号重号、编号前缀不串任务。
- 联系人只取明确关联的可见客户组织及下级，不按名称推断、不包含兄弟组织。按已有决策角色优先，但不宣称已确认项目关键人。
- 原推进建议接口仍使用编号；存在多个可见同编号商机时阻止从新详情/列表进入，提示核对，不静默选取第一条。本批未迁移全局商机 ID 或重构旧作战接口。
- 切换模块关闭详情；详情自适应手机。未改后台权限和正式业务数据。

## 验证范围

- opportunity-detail.mjs：精确身份、同账号编号前缀、跨账号同编号待办、已完成排除、日期排序、明确组织及下级、兄弟组织排除、缺关联及循环保护。
- crm_simplification_browser.py：增加客户跳转详情、联系人/空待办、工作台精准详情、编号前缀不混入、真实计划展示及390px抽屉检查，同时保留前两批回归。
- 前端全套纯函数测试、生产类型检查与构建、临时数据浏览器回归；不使用正式客户数据测试写入。

## 验证结果

- 13组前端纯函数测试全部通过；生产类型检查/构建通过，既有日记样式与大包提示保留。
- 隔离浏览器完整通过；另用合成授权快照验证跨账号同编号打开准确详情、不混入另一账号待办、推进建议重号阻断。桌面及390px详情截图已核对，768/390px工作台与原客户流程回归通过。
- 新前端构建通过既有挂载目录提供；本批未改后端、未再次重启、未推送 Git。未宣称后端全量回归或真实业务账号验收完成。
