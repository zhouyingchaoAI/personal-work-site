# 联指经营助手子工程拆分

目标：集中维护前后端业务源码，保持页面、API、权限、存储位置与后台任务行为不变。不创建独立账号体系、不迁移数据、不改变业务计算。

## 工程边界

- 子工程：`ai-office-assistant-web/packages/joint-command/`，位于现有 Node 工程中，直接复用其已安装依赖与锁文件。
- `frontend/`：原 CrmAssistantView 的全部组件、样式与业务算法。
- `backend/`：原 backend/crm*.py 的业务实现。
- 平台继续提供共享 API 客户端、会话、工单附件组件及资源；显式通过相对路径引用，不复制公共服务。
- 原后端模块保留薄加载入口，运行时执行顺序和共享命名空间保持原状；不是可单独部署的微服务。
- 原前端目录保留兼容入口，其他源码与测试改用子工程路径。

## 步骤

1. 保存迁移清单及源码摘要，先运行后端联指测试作为基线。
2. 迁移组件源码，重定位跨边界引用，平台改用子工程入口；配置子工程类型检查与开发、构建、测试命令。
3. 迁移后端业务实现，添加兼容加载器；补充宿主和 Celery 的 Docker 挂载。
4. 更新依赖路径的测试与维护文档，新增兼容加载、源码完整性验证。
5. 类型检查、生产构建、前后端回归和页面冒烟通过后更新运行实例。

## 验证原则

后端业务文件逐字节迁移；前端只变更模块外部路径。不得通过更改业务逻辑修复本次拆分无关的历史测试失败。所有历史失败需明确记录。
