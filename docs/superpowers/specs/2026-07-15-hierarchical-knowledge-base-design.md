# 分级知识库设计

## 目标

将现有“企业共享知识库 + 个人知识库”的平铺数据集列表改为不限层级的知识库树。企业节点由管理员维护、所有登录用户可读；个人节点仅当前用户可见。已有知识库和其中的文档、会话选择均保持可用。

## 方案选择

可选方案包括：以名称约定模拟目录、在前端本地保存树关系、以及在服务端保存数据集元数据。采用第三种：服务端元数据映射。它不修改 RAGFlow 的数据集内容，能跨浏览器和用户稳定显示树结构，也能在以后替换知识库引擎时保留业务层级。

## 数据与权限

- 在 `user_data/knowledge/` 保存数据集元数据：数据集 ID、`parent_id`、所属根（`enterprise` 或 `personal`）、创建者和创建时间。
- 企业根为现有共享数据集；个人根为用户默认个人数据集。根节点不可删除。
- 旧的个人数据集会自动挂在该用户个人根下；现有共享数据集仍是企业根。
- 企业节点：管理员和超级管理员可新建/删除，所有用户可浏览、检索和问答。
- 个人节点：仅创建者可新建/删除、浏览、检索和问答。
- 删除含子节点的节点将被拒绝，避免误删整棵树；用户需先处理子节点。

## 接口与前端

- `GET /api/knowledge/kbs` 返回 `parent_id`、`root_type`、`can_manage` 和树顺序所需的元数据。
- `POST /api/knowledge/kbs` 的创建请求带 `parent_id`；后端据此决定企业或个人租户、权限和父子关系。
- Vue 知识库侧栏改为可展开/收起的树；选中节点后维持现有文档上传、文档列表、检索与问答行为。
- “新建”操作在当前选中节点下创建；无权限时不显示。删除操作仅显示给可管理且非根节点。

## 兼容与验证

- 未配置 RAGFlow 时保留当前内置引擎的两个只读根节点，不展示创建操作。
- 原有 API 的 `scope` 继续使用数据集 ID；会话中保存的知识库 ID 无需迁移。
- 新增后端单元测试，覆盖：树形元数据、企业/个人权限、迁移归位和删除保护；新增前端静态测试，覆盖树字段与父级创建请求。
- 构建前端并运行相关知识库测试，最后重建并重启 Docker 的 `personal-work-site` 服务。
